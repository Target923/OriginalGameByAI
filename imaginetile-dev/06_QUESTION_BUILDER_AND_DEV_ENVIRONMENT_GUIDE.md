# 🛸 Part 1. 問題追加・検品スタジオ (`question_builder.html`)

## 1. 開発背景と目的

『IMAGINE TILE』において、問題データ（画像・答え・ヒント）の追加には以下の課題がありました：
* **手動登録の負担**: Unsplash API から画像URL、撮影者名、プロフィールURL、写真ページリンク、ダウンロード通知エンドポイントを手作業で登録するのは手間がかかる。
* **画像と答えの不一致事故**: 画像検索APIは「主題」ではなく「タグや周辺要素」でヒットするため、完全自動で画像を取り込むと「キリンを検索したのにビールの写真」「時計を検索したのに手元の写真」といった不一致事故が発生していた。
* **データベースを持たない静的HTML構成との両立**: 本作はサーバー不要・単一HTMLで完結する設計であるため、外部DBを使わずにサクサク問題を追加・マージできる仕組みが必要だった。
* **API無料枠の制限**: Unsplash Free API は **50リクエスト/1時間** の制限があるため、無駄遣いを防ぎ残数を常に把握できる仕組みが必要だった。

これらをすべて解決するため、**「面倒な情報取得は全自動 ＋ 人間が1問1秒で目視確認して承認」** する専用スタジオとして `imaginetile-dev/question_builder.html` を開発しました。

---

## 2. 実装アーキテクチャ＆主要機能

### ① Unsplash API 50回/h リアルタイム監視メーター
* **リアルタイム残数表示**:
  APIレスポンスヘッダー（`X-Ratelimit-Remaining`, `X-Ratelimit-Limit`）を解析し、ヘッダーに `⚡ 残り XX / 50 回` をプログレスバーとともに常時表示。
* **リセットまでのカウントダウン**:
  `X-Ratelimit-Reset`（UNIXエポック秒）をもとに、1時間ごとのリセット枠までの残り時間（例: `⏳ リセットまで: 約 48 分`）を1秒ごとに自動更新。
* **枯渇防止セーフティ機能**:
  - 残数10回以下: イエロー警告表示
  - 残数5回以下: レッド点滅警告
  - 残数1回以下: 一括検索ボタンを自動無効化し、枠の完全枯渇を未然に防止。
* **最小コストでの残数確認**:
  ［🔄 残数確認］ボタンにより、わずか1件の軽量クエリで最新のレートリミット状態をいつでも取得可能。

### ② APIキーの安全管理（GitHub流出ゼロ）
* **ブラウザ `localStorage` 保存方式**:
  APIキー（`WpMxqT4...`）は、画面右上の入力欄からブラウザの `localStorage['imagine_tile_unsplash_key_v1']` にのみ安全に保存されます。
* **ハードコーディングの完全排除**:
  HTMLファイルやJSコード内にはキーを一切直書きしないため、GitHubにコミット＆プッシュしてもキーが全世界に流出したり、GitHubのシークレットスキャナーで検知・無効化されるリスクがゼロです。

### ③ 1問1秒 高速目視検品カード（不一致ゼロUI）
* **複数単語の一括入力＆5大プリセット**:
  - 🍱 定番料理 10選（オムライス、餃子、天ぷら、うどん、そば、カレーライス、焼肉、豚カツ、たこ焼き、お好み焼き）
  - 🍰 カフェ・デザート 10選（ワッフル、マカロン、かき氷、大福、カヌレ、エクレア、アップルパイ、団子、シュークリーム、チュロス）
  - 🦁 動物・生き物 10選（ラッコ、カピバラ、アルパカ、ミーアキャット、ナマケモノ、ハリネズミ、オオカミ、チーター、アザラシ、シロクマ）
  - 🚗 乗り物 10選（ロケット、気球、潜水艦、ヨット、バイク、モノレール、ブルドーザー、ショベルカー、タンカー、人力車）
  - 🗼 世界の名所 10選（富士山、東京タワー、エッフェル塔、ピラミッド、自由の女神、凱旋門、万里の長城、コロッセオ、タージマハル、サグラダファミリア）
* **写真切り替えリボン**:
  Unsplash検索で取得した上位18枚の写真をサムネイルリボンで一覧表示。`[←]` `[→]` キーまたは矢印ボタンで、一番クッキリした写真に瞬時に切り替え可能。
* **既存問題との重複検知**:
  ゲーム本番の既存102問（`DEFAULT_Q`）の答えを内蔵しており、既出の単語を入力した場合は `⚠️ 既に登録済みです` バッジを自動表示。
* **表記揺れ（`YOMI_TABLE`）の自動サジェスト**:
  - ひらがな化（例: `オムライス` ➔ `おむらいす`）
  - 英語・ローマ字辞書変換（例: `omurice`, `omelet rice`）
  - カスタムタグ追加・削除機能
* **キーボード操作**:
  - **`[Enter]`**: 承認してストックに追加し、次の単語へ
  - **`[Space]`**: この単語をスキップ
  - **`[←]` / `[→]`**: 候補写真を切り替え

### ④ 4種の出力形式（DBなしで本番に即反映）
承認された問題は下部のストックに保存され、以下の4形式で出力できます：
1. **`DEFAULT_Q` コード (JS)**:
   `imagine_tile.html` の `const DEFAULT_Q = [...]` にそのまま貼り付け可能なJavaScript配列。
2. **`YOMI_TABLE` コード (JS)**:
   回答判定用の表記揺れ辞書にそのまま貼り付け可能なオブジェクト。
3. **`JSON 保存` (`approved_questions.json`)**:
   手元に保存・バックアップするためのJSONファイル出力。
4. **`Gemini 取り込み依頼文`**:
   Geminiのチャットにそのまま渡せるプロンプト文面。

## 3. 問題追加の標準作業手順

```text
1. imaginetile-dev/question_builder.html をブラウザで開く
   ↓
2. 初回のみ、右上のキー欄に Access Key を貼り付けて［保存］
   ↓
3. キーワード入力（またはプリセットボタンを選択）
   ↓
4. ［🔍 この単語を検索］（API 1回消費の安全モード）を押す
   ↓
5. 中央の検品カードで写真を確認
   ・別の写真が良い場合: [←][→] キーで切り替え
   ・表記揺れを追加したい場合: YOMI欄に入力して追加
   ↓
6. [Enter] キーで承認！（ストックに追加され、次の単語へ進む）
   ↓
7. すべて検品完了後、下部の「DEFAULT_Q コード」または「Gemini 取り込み依頼文」をコピーして本番に反映
```

# 💻 Part 2. 自宅 ↔ 会社 開発環境＆引き継ぎワークフロー

## 1. なぜ Antigravity はセッションを自動クラウド同期しないのか？

### Claude と Antigravity の根本的な構造の違い
* **Claude（Claude.ai / Projects）**:
  ブラウザのクラウドサーバー上で動作しています。GitHub連携もOAuthでクラウド上にコードを読み込むため、どのPCから開いても同じチャット履歴が見えますが、**あなたのPCのローカルファイル（`C:\Users\...`）を直接書き換えたり、ローカルのPowerShellでテストを実行することはできません**。
* **Antigravity 2.0 / CLI (`agy`)**:
  あなたのPCのローカル環境で直接動作する**デスクトップ開発エージェント**です。PC内のファイルを直接編集し、テストコマンド（Node.jsやgit）をそのPCのシェルで直接実行します。

### CLI同士・GUIアプリ同士を直接繋げない理由
Antigravity は「そのPCのローカルディスク」に密結合しています。もし会社PCのセッションと自宅PCのセッションが混ざり合うと、**「Geminiがファイルを編集した時にどちらのPCのファイルが書き換わるのか」「テストコマンドはどちらのシェルで実行されるのか」** が競合・衝突してしまうため、1セッション＝1台のPC環境に紐づく設計になっています。

## 2. Gitをハブとした完全引き継ぎ運用（ベストプラクティス）

「会社と自宅で別のチャット画面になっても、仕様の議論や設計意図を100%維持する」ための王道運用です。

### ① 作業終了時（退勤時・帰宅前）
コードの変更だけでなく、**「議論した背景・なぜその設計にしたか・次回やること」** をドキュメント（`HANDOVER_MASTER.md`）に反映した上でプッシュします：
```bash
git add .
git commit -m "[Gemini] feat(imaginetile): ..."
git push origin main
```
> **AIへの指示例:**
> 「自宅（または会社）のPCに引き継ぎたいので、今回の仕様決定の背景・議論した経緯・次回やるべきことを `HANDOVER_MASTER.md` に追記してコミット＆プッシュしておいて」

### ② 別のPCで作業開始時
1. 別のPCでリポジトリを最新化：
   ```bash
   git pull origin main
   ```
2. Antigravity 2.0（または CLI）を起動し、新規チャットの入力欄に：
   > **「`@HANDOVER_MASTER.md` を読んで現状の仕様と進捗を把握した上で、続きの作業を進めてください」**

これだけで、別のPCのGeminiも：
- 担当境界（Geminiは `imagine_tile.html` のみ、Claudeの `search_battle` には触れない）
- コミットプレフィックスルール（`[Gemini]`）
- 最新のエネルギー・初期コア数理仕様、上限5000、UI拡張
- 前回の改善議論（5人満員時の機体解除・スワップ機能、ウィンドウ高さリサイズ）
- 問題追加スタジオ（`question_builder.html`）の存在と仕様
を完全に理解した状態でスムーズに合流できます。

## 3. プロジェクト協調＆コミットルール

* **コミットプレフィックス**:
  Geminiが行うコミットは、必ず先頭に `[Gemini]` を付与します（ユーザー様がGitHub上で誰の作業か一目で識別できるようにするため）。
  - 例: `[Gemini] feat(imaginetile): add question_builder studio ...`
* **AIごとの担当領域境界（厳守）**:
  - **Gemini（当エージェント）担当**: `imagine_tile.html`, `imaginetile-dev/*`
  - **Claude 担当**: `search_battle.html`, `searchbattle-dev/*`, `サーチバトル.html`
  - **共有ファイル**: `index.html`（総合ランチャー）、`shift_and_shaft_game.html`（完成済み）
  - ※お互いの担当領域のコードやドキュメントには絶対に勝手に手を加えないこと。
