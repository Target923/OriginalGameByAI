## 3. P2Pオンライン協力マルチプレイ（実装済みアーキテクチャ仕様）

`imaginetile-dev/it_multi.js` および `imagine_tile.html` 本体に統合された **ホスト権威型スター接続（Host-Authoritative Star Topology）** の実装仕様です：

1. **通信トランスポート層 (`ITMulti.openPeerRoom` / `joinPeerRoom`)**：
   - **インターネット経由**：PeerJS（`imaginetile-<6文字コード>`）によるWebRTC DataChannel直接通信。サーバー維持費ゼロでGitHub Pages上から動作します。
   - **同一ブラウザ別タブ／ローカル検証**：`BroadcastChannel` を自動併用（URLに `?net=local` を付与すると完全オフラインのローカルタブ専用モードとしても起動可能）。
   - **ローカルPeerServer切替**：URLに `?peer=127.0.0.1:9000` を付与することでローカルシグナリングサーバーへの接続にも対応。
2. **ロビー＆機体排他ロック (`ITMulti.HostRoom` / `GuestClient`)**：
   - 定員2〜5人（6人目および試合進行中の途中入室は自動拒否）。
   - 5機のホバーカー（`unitIdx: 0..4`）は排他選択。他プレイヤーが搭乗中の機体はロック表示され、自分の機体を再クリックすると搭乗解除（`unitIdx = -1`）して5人満員時でもお互いの機体を入れ替えられます。空き機体への移動・未搭乗ステータスバー・READY状態・ホストのワールド／モード／エネルギー設定変更がリアルタイムで全員に同期されます。
3. **バトル同期プロトコル**：
   - **`match_init` / `q_init` / `q_go`**：ホストが出題データ（カスタム問題含む）・盤面サイズ・視覚デバフ乱数 (`diff`)・初期バリア (`barrier`)・初期ツタ (`vine`)・タイル色シード (`paletteSeed` / `mulberry32`) を全員へ配信し、全端末で100%同一の盤面を生成します。
   - **`act` ➔ `ev`（アクション権威判定）**：ゲストの `shot` / `cannon` / `spec` / `ans` 要求をホストが一元検証・乱数確定し、結果イベント (`ev`) と最新プレイヤーステータス (`playersSync`) を全員へブロードキャストします。他の仲間が攻撃しても、自分がエイム中の指定型SPECIALは解除されず継続できます。
   - **`tick` / `vine_spread`**：ホストのマスタータイマーが1秒ごとに残りミリ秒を補正配信し、JUNGLEの3秒ごとのツタ侵食位置も完全一致させます。
   - **`bonus_pick` ➔ `bonus_status` ➔ `bonus_commit`**：レベル突破時、各プレイヤーが自分の画面で「⚡エネルギー」か「💎コア」を選択し、全員選択完了（または30秒安全タイマー経過）で一括反映して次ステージへ進みます。
4. **自動テストスイート**：
   - `node imaginetile-dev/test/net_multi_sim.js`：数理計算・5人ロビー・重複防止・定員拒否・途中切断引継・HTML構文検証。
   - `node imaginetile-dev/test/e2e_runtime_test.js`：`imagine_tile.html` 実スクリプトを用いた3機オフライン自由編成＆3人BroadcastChannel実通信E2E検証。
